## Overall Impression

The system is disciplined and reads as premium at a glance — but the two most consequential problems both sit directly on top of this page's one job (get read, get contacted): the content-hiding animation/accordion pattern has no no-JS fallback, and the accordion has no keyboard path, so a meaningful share of this page's actual content is invisible to some of the exact audiences most likely to view it (ATS scrapers, screen-reader users, restrictive corporate browsers). Layered on top, the one color used for the page's credibility markers — kickers, labels, cert-verify links — fails WCAG AA contrast. The single biggest opportunity is closing those two gaps before touching anything cosmetic: the visual system is already good enough to ship, but right now it's actively hiding the story it was built to tell from a chunk of the people meant to read it.

## What's Working

- **The stat-list component** (`1,000+` / `3` / `~8`) turns the resume's core credibility claim into a glanceable, persistent object instead of leaving it buried in a paragraph — the best single piece of information design on the page.
- **The Renault accordion's nested-role structure** does real design work: three role blocks inside one company entry, closed by a synthesizing note, visually enacts "one continuous system" rather than just asserting it in prose.
- **Typographic discipline**: Fraunces is confined to identity/emphasis moments (name, kickers, company titles, stat numbers), Inter carries every body/label instance — no third face, no arbitrary weight drift, a genuinely calm reading rhythm sustained across all six sections.

## Priority Issues

**[P0] Most content is invisible or unreachable without JavaScript.**
- **Why it matters**: Nearly every content block carries `.reveal` (`opacity:0`, only flipped visible by an `IntersectionObserver`), and three of the four experience rows (Ingenico, Paris-Dauphine, Sofrecom) default to `max-height:0`, opened only by a JS click handler with no static fallback. If the script errors, is blocked, or never runs — a corporate browser policy, an ATS content scraper, JS disabled — the page for a surface whose entire purpose is "get read" renders as an almost-empty hero plus one pre-opened job. This directly threatens the site's stated success metric.
- **Fix**: Gate `.reveal{opacity:0}` behind a `.js` class added by an inline head script (so content defaults to visible without JS) and give the collapsed experience rows a no-JS-safe layout instead of a hard `max-height:0` default.
- **Suggested command**: $impeccable harden

**[P0] The experience accordion is not keyboard-operable.**
- **Why it matters**: `.exp-top` is a plain `<div>` with a click listener — no `tabindex`, no `role="button"`, no keydown handler, no `aria-expanded`. (The rail nav gets this right, using real `<button>` elements.) A keyboard-only user cannot open Ingenico, Paris-Dauphine, or Sofrecom — 75% of the listed work history is permanently unreachable without a mouse.
- **Fix**: Convert `.exp-top` to a real `<button>`, or add `role="button" tabindex="0"` with Enter/Space keydown handling and `aria-expanded`.
- **Suggested command**: $impeccable harden

**[P1] The accent gold fails WCAG AA contrast on small text.** *(confirmed by the deterministic scan: `#A1752B` on `#E4E3DC` measures 3.2:1, needs 4.5:1)*
- **Why it matters**: This affects every kicker ("Who I am", "Where I've worked"), the hero eyebrow, certification "verify" links, and both hover states in the footer/quicknav — all set below the 18px large-text threshold, so all need 4.5:1 and don't get it. (The 34px stat numbers are large enough to only need 3:1 and do pass — so this is specifically a small-text problem, not a blanket ban on the color.) These are exactly the labels and trust-markers meant to build credibility, rendered in the page's hardest-to-read color.
- **Fix**: Darken the small-text gold instances toward WCAG AA (or increase weight/size where the design allows), while keeping the existing large-text uses (stat numbers) as-is since they already pass.
- **Suggested command**: $impeccable audit

**[P1] The contact section carries no visual escalation over the rest of the page.**
- **Why it matters**: `.contact-block .row` is styled almost identically to `.cert-item` rows three sections earlier — same hairline border, similar type scale. The "Rare Gold Rule" (no filled buttons) is a legitimate stance, but it means the page's one actual conversion moment (a recruiter using this section to reach out) carries the same visual energy as a certification badge.
- **Fix**: Give the email row one deliberate step-up within the existing vocabulary — larger display-scale type, or a specific gold-marked emphasis consistent with "gold marks, never fills."
- **Suggested command**: $impeccable bolder

**[P2] Mobile has no navigation until the page is fully scrolled.**
- **Why it matters**: `nav.rail` is `display:none` below 820px, and the only substitute — `.quicknav` — sits physically after the Contact section at the bottom of the DOM. On the device most likely used for a quick first scan, there's no way to jump to Experience or Skills without scrolling past everything or already knowing the bottom nav exists.
- **Fix**: Add a lightweight mobile nav (a collapsed top bar or sticky control) instead of relying solely on the trailing quicknav.
- **Suggested command**: $impeccable layout

## Persona Red Flags

**Sam (Accessibility-Dependent User)** — primary action: tab through the page or use a screen reader to evaluate the candidate.
- Cannot reach 3 of 4 companies' content via keyboard at all — a screen-reader or keyboard user's picture of this candidate is silently missing everything before Renault.
- The rail nav's label tooltip only fires on `:hover` (not `:focus-within`), so a sighted keyboard user tabbing the rail sees an outline around a bare 7px dot with no visible label text for what section it targets.
- No `:focus-visible` styling exists anywhere in the stylesheet — focus indication on the two dark sections relies entirely on the default browser outline, with nothing added to compensate for the darker ground the system itself introduced.

**Riley (Deliberate Stress Tester)** — primary action: rapid clicking, resizing, probing edges.
- `.exp-body{max-height:900px}` is a hardcoded cap, not `auto` — content past that height (browser zoom, a future fourth Renault role) would silently clip with no visible cue more exists.
- The portrait `<img>` has no `onerror` handling — a failed load shows a broken-image glyph inside the circular, shadowed, glow-haloed frame that's the literal first thing on the page.
- `.exp-role{grid-template-columns:220px 1fr}` uses a fixed-px first column that doesn't reflow at high browser zoom the way an `fr`/`ch`-based column would.

**Casey (Distracted Mobile User)** — primary action: opens the link on a phone, scans in a few seconds.
- Zero wayfinding until scrolling to the very bottom — a ten-second scan-and-bail visit never surfaces the page's own table of contents.
- `.skill-cat .cat-name{width:190px; flex-shrink:0}` holds a fixed 190px label column even on a ~360px phone, leaving ~170px for the Google Cloud category's 16 wrapping tags — a tall, cramped tag wall that's expensive to thumb-scroll past.
- The hero's mailto link has no padding — its tap target is exactly the 13px text glyph, the smallest, most imprecise target on the page, on the link most likely to be tapped first.
